# 电量与费用定义

id为计量号、order为订单号、station为站点，均为字符串。kind取order或station。计量start/end必须带时区，区间[start,end)，最大72小时可调至168小时。energy以kWh或MWh输入，输出kWh。未知哨兵不等于零。
费率版本以本地+08日期[from,to)生效；日内时段必须完整无重叠覆盖0–24小时。默认11月17日调整尖峰价，可在API参数tariffs中提供相同结构版本清单。
计量段内假定匀速用电，电量按时长交集分配，最后一段修正Decimal除法尾数保证电量严格守恒。跨日以当地日期重选版本。
每站唯一总表电量减订单电量为损耗，按订单kWh占比分配。总表缺失、重复、负损耗或无订单承接损耗时标记异常，不强行分配。
订单应收=各分时电量×费率+损耗份额×loss_rate。站内先按整站费用取整再最大余额分币，稳定id打破余数并列；渠道逐单按分四舍五入扣款。JSON金额为Decimal字符串。账单bill为CNY，差额=应收-bill，容差边界包含。

逐单对账以同一未舍入金额 raw_amount 为基准：逐单四舍五入应收 expected=ROUND_HALF_UP(raw_amount,2)。站内分单 amount 与 expected 只可能相差一分。若渠道实扣 bill 恰等于 expected，则该一分差为取整路径不同造成，记“取整差”（办结），站点应收保持 amount 且不向客户催缴；若 bill 低于 expected 为实际少扣、高于为实际多收，逐单“待核查”，同站另单多收或总额刚好持平都不抵消。站级 receivable=Σamount、received=Σbill，二者分开列示，不按实收改写应收。

复核决定：通过/退回走乐观锁；确认尾差只登记办结单的取整差，批次内以站点+订单唯一定位，重试同一批不重复确认且不递增版本。存在待核查单时结算结论为挂起。
版本最高者采信，同版冲突全部隔离；重复和旧版计入隔离。输入行数=采信+隔离。批次哈希包含输入摘要、规则版本、参数；复核乐观锁防止旧提交覆盖。

站点总表区间必须覆盖其全部订单区间；未覆盖标记总表未覆盖订单区间，损耗不强制分摊，账单结论为待复核。
